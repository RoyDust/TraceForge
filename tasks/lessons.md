# Lessons

被用户纠正后沉淀的规则，避免重复犯。

- **用大白话，不用自造黑话**：不要用「神圣点 / 神圣叙事」这类词指代「要重点做深的功能」。直接说「要做深的两块」「核心卖点」「重点功能」。
  - 起因：grill 决策时反复用「神圣点」，用户要求换成正常易懂的表达。
- **桌面控制台优先区域内滚动**：侧边栏和工作区必须受视口高度约束，长列表与详情内容在各自卡片或列内滚动，避免 body 带着整个控制台上下移动；移动端再恢复自然页面滚动。
  - 起因：用户检查高保真控制台时指出追踪运行等侧栏缺少高度限制，整体页面滚动影响操作稳定性。
- **固定壳层后逐页验证根容器**：不能只验证 Dashboard、Trace 和 Prompt/Eval；所有控制台页面都要确认根容器不会用旧 `min-height` 撑开视口。看起来像按钮的控制必须有真实状态与键盘语义，不能用静态元素占位。
  - 起因：Chat 页仍能整页滚动，且侧边栏“收起”只有外观没有交互逻辑。
- **性能优化不删减产品能力**：当用户要求功能完整时，不能把减少查询量误解为删除指标、面板或流程；应保留完整功能口径，只替换为聚合、分页、预计算或分层查询等可扩展实现。
  - 起因：讨论 Dashboard 优化时曾建议只保留部分数据读取，用户明确要求所有功能继续保留，Redis 仅后置。
