TraceForge

把 AI 调用从黑盒变成可观察、可归因、可评估的系统。

当前讲解基于本仓库最新实现：Chat Playground、Gateway、TraceRun、Dashboard、Prompt、Eval 已形成本地闭环。

Plain-language tour

AI 请求不再是黑盒。

TraceForge 像一个站在模型前面的透明网关：你的应用照常发 AI 请求，它负责转发、鉴权、限流、记录证据。 然后你在 Console 里看到这次调用的输入、输出、耗时、token、成本和失败原因。

OpenAI Compatible Rust Gateway Next.js Console PostgreSQL Trace
1 业务应用把 AI 请求先发给 Gateway，而不是直接发给模型。
2 Gateway 一边转发给上游模型，一边把调用过程写进数据库。
3 Console 把数据库里的 TraceRun 展示成瀑布图、成本看板、Prompt/Eval 证据。

Project map

项目由三层组成。

点左边任意模块，右边会解释它在系统里的位置。最重要的是：Gateway 是数据面，Console 是控制面，PostgreSQL 是共同事实源。

业务应用 / Chat

它是请求的发起者。真实业务应用可以把 baseURL 指到 Gateway；本项目还提供 `/chat` 页面，让你不用写 curl，也能从网页发起一次测试调用。

  • 请求形状仍然是 OpenAI-compatible。
  • Chat 页面不会暴露项目 API Key。
  • 每次测试都会跳到对应 TraceRun。
